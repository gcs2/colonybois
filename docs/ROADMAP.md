# Roadmap and acceptance gates

Current ordering, 24 September 2026. The [task board](TASK_BOARD.md) owns task status and next actions; this document owns milestone boundaries. [Older city-first milestones and accumulated checkpoints](history/ROADMAP_2026-09-24.md) are retained as history. They are not prerequisites for the space game.

| Milestone | Deliverable | Gate before widening |
|---|---|---|
| 1. Convincing personal journey | Responsive flight and scale navigation; coherent surface/system/galaxy views; readable inventory/contact/trade; finite costs, consequence and saves | Complete a three-world voyage, contact/trade, earn and buy an upgrade, encounter danger, return and resume a save. Smoke-launch a clean Windows export and verify save/reload of this voyage. Complete the bounded accessibility/input review. |
| 2. Inhabited, explorable worlds | Shared geography from globe to traversable ground, meaningful destinations/resources, city/port activity and clear communications | Geography agrees across scales; traversal and revisits work; bounded memory/frame time; visible life supports actual services and choices. Record a performance budget on named target hardware before passing this gate or scaling world fidelity/caps. |
| 3. Agreed Space Stage baseline | Remaining reference families integrated into one campaign, with approved exclusions accounted for | Reference ownership/coverage closed; end-to-end play, persistence and user review of fun/art/audio pass. A fresh or branched replay yields at least two distinct, viable paths whose choices change routes, resources, relationships or rewards in the persistent history. Confirm the clean Windows export saves/reloads the campaign and all applicable performance budgets hold. Tests or an item count alone cannot pass this gate. |
| 4. Content and story enrichment | Distinct resource/species/civilization content, combinations, supply chains and living ancestor story | New content creates meaningful decisions using proven systems; authored asset/acting loop has passed before cast multiplication. |
| 5. Later capabilities | Human Sol start, richer factories, on-foot/first-person and broader fleet possibilities as prioritized | Each needs its own bounded feasibility/playability proof and explicit scope decision; none is silently added to the current milestone. |

Reference research and every-view mocks support all milestones; they do not replace playable delivery. Work is currently before the first milestone's human acceptance gate, despite numerous implemented systems. The Field Instruments direction is selected; final playable visual/audio quality is not accepted.

Across M1-M3, every implemented view/state must trace to approved canon, have same-state runtime evidence, and receive separate independent-critic and user verdicts. A bounded accessibility/input review covers legibility at supported resolutions, visible keyboard focus, mouse and supported keyboard paths, reduced motion, and visual or caption equivalents for essential audio/VO. Define and record each relevant performance budget on named target hardware before passing or scaling that gate; numeric thresholds come from measurement, not this roadmap.

Every milestone must remain reproducible and reviewable from a clean checkout of the canonical Git repository. Keep approved canon, prompts/briefs, provenance and required source assets in documented tracked locations; never make an ignored worktree artifact the only copy of required content or acceptance evidence. Isolated worktrees are execution sandboxes, not competing sources of truth.

Character modeling and corpus production are deferred. Coloring and terrain sculpting are excluded; further planet modification remains deferred. Existing climate/ecosystem mechanics stay intact. Cities support the space experience through aggregate simulation. No mandatory long city tutorial, engine migration or freeform creature creator is introduced by this roadmap.

Forecast only after measuring completed, reviewed slices. Preserve dated estimates in History; do not turn prototype code volume or generation speed into a promise of finished-game dates.
